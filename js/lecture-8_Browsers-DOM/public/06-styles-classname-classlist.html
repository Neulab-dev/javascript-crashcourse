🎨 DOM Styles - style, className, classList

Three ways to modify element styling:
  • element.style: Direct inline style manipulation (lowest priority in CSS cascade)
  • element.className: Get/set all classes as a string
  • element.classList: Modern API to add/remove/toggle individual classes

1. Inline Styles with element.style

Directly modify CSS properties through the style object:

const elem = document.getElementById('myElement'); elem.style.backgroundColor = 'blue'; elem.style.color = 'white'; elem.style.padding = '1rem'; elem.style.fontSize = '20px';

Demo:

Original styling
Note: CSS property names are camelCase in JS (font-size → fontSize, background-color → backgroundColor)

2. Reading Inline Styles

Read current inline style values:

const elem = document.getElementById('myElement'); const bgColor = elem.style.backgroundColor; const color = elem.style.color; const padding = elem.style.padding;

Demo:

Element with inline styles
Important: element.style only reads INLINE styles. Computed styles (from CSS classes) need getComputedStyle()

3. className - Get/Set All Classes

Replace all classes at once using className:

const elem = document.getElementById('myElement'); // Get all classes as a string const classes = elem.className; // "class1 class2" // Set classes (replaces all) elem.className = 'newClass1 newClass2';

Demo:

Original classes
Caution: className replaces ALL classes. Adding a class with className removes existing classes!

4. classList - Modern Class Management

The classList API allows safe manipulation of individual classes:

const elem = document.getElementById('myElement'); elem.classList.add('myClass'); // Add a class elem.classList.remove('myClass'); // Remove a class elem.classList.toggle('myClass'); // Add if not present, remove if present elem.classList.contains('myClass'); // Check if has class (returns boolean) elem.classList.replace('old', 'new'); // Replace a class

Demo:

Element with multiple classes

5. classList.add / classList.remove

Add or remove multiple classes at once:

elem.classList.add('class1', 'class2', 'class3'); elem.classList.remove('class1', 'class2');

Demo:

Click buttons to modify classes

6. classList.toggle

Toggle a class on/off. Perfect for switch-like behavior:

elem.classList.toggle('active'); // Adds if not present, removes if present elem.classList.toggle('active', true); // Force add elem.classList.toggle('active', false); // Force remove

Demo:

7. Reading Computed Styles

Get actual computed styles (including from CSS classes) using getComputedStyle():

const elem = document.getElementById('myElement'); const computed = window.getComputedStyle(elem); const bgColor = computed.backgroundColor; const fontSize = computed.fontSize; const padding = computed.padding;

Demo:

Element with CSS class styles
Difference:
  • element.style - Only inline styles
  • getComputedStyle() - Final computed values (inline + CSS classes + cascading)

Method Comparison

Method Use Case Pros Cons
element.style One-off inline styles Direct, immediate Lowest priority, hard to maintain
element.className Replace all classes Simple, complete replacement Removes existing classes, string manipulation
element.classList Add/remove individual classes Modern, safe, intuitive API Requires browser support (modern browsers)
getComputedStyle() Read final computed styles Gets actual rendered values Read-only, performance cost

Best Practices

✓ DO:

  • Use classList for adding/removing individual classes (modern approach)
  • Use CSS classes for styling themes and states
  • Use element.style only for dynamic/calculated values
  • Use getComputedStyle() when you need final computed values
  • Keep styles in CSS, use JavaScript for toggling classes

DON'T:

  • Use className to add/remove classes (it replaces all)
  • Put complex styling logic in JavaScript
  • Use inline styles for anything that should be in CSS
  • Repeatedly read computed styles in loops (performance issue)
  • Mix inline styles with classes for the same properties
